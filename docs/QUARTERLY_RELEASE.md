# 每三个月手动发布清单

普通更新由站长或获授权代理手动发起。不设置任何 schedule/cron，不创建提醒，不依赖常驻进程。日期表示检查计划，不承诺无人发起时自动更新。

1. 重新探测公开 schema，核对版本；真实接口失败时保留上一版。
2. 重新枚举公开投稿，重查公开评审、决定与子评论。首次大规模运行需检查接口实际分页表现和运行时间。
3. 规范化、计算均分、排名与排除项。检查缺失分数、重复匿名代号、决定冲突、撤稿和 Desk Reject。
4. 导出到 `.cache/candidate`；至少抽查 30 篇真实论文，覆盖两个反差榜、普通录取/拒稿和边界情况。本次因接口阻挡，完成数为 0。
5. 比较证据内容哈希与 rubric。未变的已批准报告可复用；已变的标为待复核。未分析可保持空状态。
6. 校验候选，准备 release metadata，获得真实发布批准后调用 `reviewcase release` 保存不可覆盖的归档；日期保持 published_at=null，直到实际部署成功。
7. 更新经验证的当前内容，运行完整测试和静态构建。只提交允许公开的最小数据与已批准报告。
8. 手动触发 deploy-pages；确认上线后记录实际发布时间。按三个日历月计算下一次检查日，月底取目标月最后一天；纠错补丁沿用既有季度基准。

## 手动 workflow

`refresh-data.yml` 只生成经过门禁验证的公开候选 artifact，不 push，不自动部署，不调用模型。当前未核验 schema 会导致任务停止。原始响应与私有草稿不上传 artifact。

## 紧急下架

使用明确的 `forum_ids` denylist，运行 `reviewcase redact`。它不访问网络或调用模型。重建当前与历史页面，检查论文 JSON、证据、报告和搜索索引均移除目标；记录公开更正说明。普通补丁不移动季度检查基准。

## 不得省略的区分

- 投稿枚举结束与所有论坛资料成功获取不同。
- 网站抓取快照与论文原稿 / revision / camera-ready 不同。
- 引用格式校验与人工专业复核不同。
- 构建成功与真实数据验收、发布成功不同。
