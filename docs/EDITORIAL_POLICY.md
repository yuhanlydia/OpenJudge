# Report policy

Only public, precisely identified evidence may support a claim. A human editor must verify technical meaning, source version, quotations and limitations. Structural quote checks do not constitute professional review. Without the original submission, claims that the original already contained a result stay unverifiable; later camera-ready material cannot substitute for it. Decisions and reviewer scores do not imply error or motive.

Work drafts remain private to the site owner. A public pull request is public, even before merge. The import command checks referenced evidence IDs, source quotes, bundle hash, and explicitly supplied external approval record; it does not call a paid model or create its own approval record. Model names supplied by users have `model_provenance=user_reported` or `unknown`, not `api_verified`. Changed evidence marks prior analysis stale; a historical report remains bound to its original release. The editorial flow is `not_generated → draft_private → schema_validated → evidence_checked → approved → published`.

Suggested report structure: source and model provenance; Stage A blinded original-version claim checking; Stage B public rebuttal and revision context; Stage C public decision explanation; supporting and counterevidence per claim; writing diagnosis for paper and review; specific limitations. All rewrites must cite existing fact IDs and await human semantic review.

Approval records must be created by an authorized editor outside the import process and bind a digest of the exact allowlisted report content, report ID, evidence bundle hash, rubric version, editor, and approval time. A refreshed capture date alone does not stale a report when the evidence content and rubric are unchanged. A changed review or version hash does. Emergency redaction persists a denylist, removes affected records and evidence from current/historical snapshots, and prevents re-export of those forum IDs; it is an exceptional correction, not ordinary quarterly history editing.
